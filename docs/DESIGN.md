# Design challenges when developing this project
This project requires python as the main driver for the analysis/optimization/exploration process.
This is limiting because my proposed solution has to interact with external programs.

## Use case for external programs
The user writes some code snippet in C/C++/FORTRAN and makes it available from the python runtime.
This could even be generated by some custom logic or DSL, it doesn't matter.

An external compiler is called to produce the IR.
The compiler must be selected based on the language and IR requirements.
At this moment, the python runtime needs to know the path of the tool.

The IR is loaded back into python (as a human readable IR) and then the user can operate on it by calling once again external tools.
The user can run passes on the IR according to some exploration logic, which is domain specific.
It's for this reason that I want to use python and jupyter notebooks as it's very versatile.

The passes may already be available from the LLVM/MLIR tools, but users require custom, out-of-tree, passes.
The framework should be able to load (and potentially compile, I'm not sure) the user passes as plugins.
Note that the passes must be compiled with "the same" toolchain as the compiler tools (i.e `opt`) that run them.

## Sources of coupling
Python needs to see where the path of tools.

I was thinking of hardcoding the paths at install time.
When the python package is installed I could potentially run code to configure the project (CMake?) and produce files that contains the paths.
This moves the coupling between python and external programs at config time, not at runtime.
